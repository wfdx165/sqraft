# 组件系统（Component System）规格

## Problem Statement

Sqraft 目前没有真正的复用能力：设计师做完一个卡片、按钮或弹窗后，只能复制粘贴出一堆互不相干的副本；改一处就要手工改所有副本，漏改一处就会在界面里出现两种版本。AI 侧同样无法产出可维护的界面——它只能逐个节点地画，既不知道「这是一个按钮」，也无法把同一套结构复用到多个位置。

文档模型里虽然已经有 `component` / `instance` 两个占位类型和 `componentId` 字段，但它们没有任何语义：渲染器把组件当矩形、把实例当虚线框，没有主组件、没有同步、没有插槽、没有属性、没有覆盖。路线图的 M2 把「组件/实例/组件属性统一模型」列为设计能力主体的一部分，术语表也已经规定「变体只是枚举型组件属性，不存在独立的变体系统」。

## Solution

引入一套以「主组件 = 有接口的容器」为核心的组件系统：

- 任意选区都能转成主组件（单容器原地转，多选自动包一层），主组件是页面树顶层的真实节点。
- 从组件面板插入实例；实例是与主组件保持同步的真实子树，可跨页面引用。
- 母版结构、样式、尺寸发生变化时，所有实例在**同一个撤销步**内同步。
- 实例内部可以双击进入编辑；任何字段级修改都会自动记成覆盖，母版更新时覆盖保留。
- 插槽（Slot）是母版里的命名内容区域，可带默认内容；实例可整体替换插槽内容，清空则恢复默认。
- 组件属性（本轮支持文本、布尔、实例替换三种）从图层创建并隐式绑定一个字段；属性优先于覆盖。
- 实例可以替换成另一个组件、可以脱离为普通画板；删除母版时实例自动脱离。
- AI 与 MCP 共用同一套工具：读写组件定义、插入实例、设属性、填插槽、切组件、脱离。

本轮不做枚举属性与变体、跨文件组件库、作用域插槽和通用拖拽重父级。

## User Stories

1. 作为设计师，我希望选中任意节点或一组节点就能创建主组件，这样我不用先手工整理层级。
2. 作为设计师，我希望选中单个画板或分组时原地转成主组件，这样布局和坐标不会跳变。
3. 作为设计师，我希望选中多个零散节点时自动包一个组件，这样「把三个按钮做成一个组件」是一步操作。
4. 作为设计师，我希望主组件始终位于页面顶层，这样删除画板不会误删母版，组件列表也能按页面稳定分组。
5. 作为设计师，我希望把一个嵌套在画板里的容器转成组件时，它自动提升到页面顶层且世界坐标不变，这样我不用手动搬动。
6. 作为设计师，我希望新组件自动命名「组件 N」，这样图层树和组件面板里能立刻认出来。
7. 作为设计师，我希望组件面板列出全文档所有主组件并按页面分组，这样我能找到放在别的页面里的组件。
8. 作为设计师，我希望单击组件面板里的组件就在活动页视口中心插入实例，这样插入位置可预期。
9. 作为设计师，我希望双击组件面板里的条目就跳转到主组件，这样我能快速回到母版修改。
10. 作为设计师，我希望主组件可以放在任意页面，这样我能用单独的「组件」页组织设计系统，也能把母版放在使用它的页面旁边。
11. 作为设计师，我希望实例在未进入时按一个整体选中，这样点一下不会误选内部图层。
12. 作为设计师，我希望双击实例进入实例上下文，这样我能像编辑普通图层一样编辑内部节点。
13. 作为设计师，我希望在实例上下文里按 `Esc` 逐级退出，这样退出行为与现有画布一致。
14. 作为设计师，我希望在实例内部选中并修改图层，这样我不用为了一个小改动回到母版。
15. 作为设计师，我希望实例内部的修改自动成为字段级覆盖，这样我不需要理解「覆盖表」这种概念。
16. 作为设计师，我希望只有被我改过的字段被冻结，母版改其它字段时仍然同步，这样实例不会因为改过一个文案就整体失联。
17. 作为设计师，我希望把字段改回与母版相同的值时覆盖自动消失，这样「恢复默认」只需要再改一次。
18. 作为设计师，我希望图层树里用标记显示哪些字段被覆盖，这样我能一眼看出实例为什么和母版不一样。
19. 作为设计师，我希望检查器能逐字段重置覆盖，也能一键重置全部覆盖，这样我能快速回到母版状态。
20. 作为设计师，我希望实例可以拖拽缩放，只改变实例框而不缩放内部内容，这样我能给同一个组件不同尺寸的容器。
21. 作为设计师，我希望没手动改过尺寸的实例跟随母版尺寸变化，改过尺寸的实例保留自己的尺寸，这样两种意图都能表达。
22. 作为设计师，我希望母版改动后所有实例立即同步，而且一次撤销就能把母版和全部实例一起还原，这样编辑是安全的。
23. 作为设计师，我希望选中母版里的文本图层就能创建文本属性，这样实例检查器里会出现一个文案输入框。
24. 作为设计师，我希望选中任意图层就能创建布尔属性，这样实例检查器里会出现一个控制该图层可见性的开关。
25. 作为设计师，我希望选中嵌套实例就能创建实例替换属性，这样实例检查器里会出现一个组件下拉。
26. 作为设计师，我希望属性有稳定的内部身份、显示名可以随时改，这样改名不会让实例上的值失效。
27. 作为设计师，我希望属性重名会被拒绝，这样组件接口不会出现两个同名控件。
28. 作为设计师，我希望删除属性后绑定字段回落到母版值、实例上的值一并删除，这样删除语义和「重置」一致。
29. 作为设计师，我希望属性绑定目标被删除时属性自动删除，这样组件接口不会留下悬空项。
30. 作为设计师，我希望被属性绑定的字段在实例里不能再写覆盖，这样一个字段永远只有一个真源。
31. 作为设计师，我希望实例上的属性值可以单独重置，重置后回落到母版当前值，这样我能表达「这个实例用默认」。
32. 作为设计师，我希望在母版里把一个容器转成具名插槽，原有子节点成为默认内容，这样我能把「标题区」「操作区」开放给实例。
33. 作为设计师，我希望一个组件可以有多个具名插槽，这样卡片、列表项、弹窗这类结构能完整表达。
34. 作为设计师，我希望插槽名在组件内唯一，这样实例侧不会出现指向不明的填充。
35. 作为设计师，我希望实例只填自己想填的插槽，没填的插槽继续显示默认内容，这样我能逐步覆盖。
36. 作为设计师，我希望实例填了插槽内容后完全替换默认内容，这样插槽语义和 Vue 一致。
37. 作为设计师，我希望清空插槽填充后恢复默认内容，这样改错可以退回。
38. 作为设计师，我希望把已有节点拖到插槽上就能填充，这样我不用重建一份内容。
39. 作为设计师，我希望从实例外部直接拖到插槽上也能填充，这样我不必先进入实例上下文。
40. 作为设计师，我希望在插槽里新建或粘贴节点时，它们自动归该插槽，这样填充是自然发生的。
41. 作为设计师，我希望插槽内容里可以再放别的组件实例，这样我能做组合型组件。
42. 作为设计师，我希望空插槽在编辑模式显示虚线占位、导出时不出现，这样我知道哪里可以填、成品又不会多出框。
43. 作为设计师，我希望图层树里插槽显示「已填充 / 默认」，这样我能看到每个实例的填充状态。
44. 作为设计师，我希望删除母版插槽时如果有实例填过内容会被拒绝并提示先清空，这样我不会在不知情时丢掉自己的内容。
45. 作为设计师，我希望删除母版里其它内部节点时实例静默跟随，相关覆盖一并丢弃，这样母版迭代不被无谓阻塞。
46. 作为设计师，我希望实例替换的下拉列出文档内所有组件，这样换组件不需要先建「组件集合」。
47. 作为设计师，我希望替换组件时按 `mainId` 交集保留覆盖、按插槽名保留内容，这样「按钮换成另一个按钮」不会丢掉已经填好的文案。
48. 作为设计师，我希望替换组件后实例位置不变、尺寸采用新组件，这样替换结果可预期。
49. 作为设计师，我希望实例可以脱离为普通画板，继承实例的填充、描边、圆角和尺寸，这样脱离后外观不变但不再受母版影响。
50. 作为设计师，我希望脱离时插槽变成普通容器、嵌套实例仍保持为实例，这样脱离只影响我选中的那一层。
51. 作为设计师，我希望删除主组件时引用它的实例自动脱离，这样不会留下坏引用。
52. 作为设计师，我希望删除含主组件的页面时先看到确认提示，确认后实例自动脱离，这样批量删除不会静默破坏页面。
53. 作为设计师，我希望把组件嵌进自己时被拒绝，这样实例永远是有限树。
54. 作为设计师，我希望图层树里实例默认折叠、展开后只读展示内部图层，这样复杂实例不会把树撑爆。
55. 作为设计师，我希望实例名默认跟随组件名、手动改名后不再跟随，这样命名既有默认又不失控制。
56. 作为设计师，我希望 `⌥⌘K` 创建组件、`⌥⌘B` 脱离实例，这样高频操作不用离开键盘。
57. 作为设计师，我希望这两个快捷键能在快捷键面板里改，这样它们和其它动作遵守同一套规则。
58. 作为设计师，我希望组件、实例、插槽、覆盖、脱离都能撤销/重做，这样试错成本可预期。
59. 作为设计师，我希望保存的 `.sqraft` 保留组件定义、实例值、覆盖与插槽内容，这样重新打开不会退化成普通图形。
60. 作为设计师，我希望非活动页上的组件与实例和页面一起淡化，这样两种模式的规则保持一致。
61. 作为设计师，我希望没有填充的画板是透明的，这样脱离出来的按钮不会凭空多一块白底。
62. 作为 AI 代理，我希望 `read_document` 返回组件定义、属性、插槽和实例状态，这样我能理解可复用的结构。
63. 作为 AI 代理，我希望 `create_node` 支持 `kind: "component"` 和 `kind: "slot"`，这样我能直接搭出组件结构。
64. 作为 AI 代理，我希望有 `create_instance` 工具，这样我能把组件放到页面上并指定属性与插槽。
65. 作为 AI 代理，我希望有 `define_property` 工具，这样我能把母版里的图层暴露成组件接口。
66. 作为 AI 代理，我希望有 `set_instance_prop` 工具，这样我能为单个实例设置文案、可见性或替换组件。
67. 作为 AI 代理，我希望有 `fill_slot` 工具，这样我能把已有节点移进插槽。
68. 作为 AI 代理，我希望有 `swap_instance` 和 `detach_instance` 工具，这样我能替换或固化实例。
69. 作为 AI 代理，我希望用现有 `update_node` 编辑实例内部节点时，覆盖被自动记录，这样我不需要额外工具就能微调实例。
70. 作为 AI 代理，我希望组件相关的颜色仍然只接受 Token 引用，这样 AI 产出的组件不会引入字面量色值。

## Implementation Decisions

### 数据模型

- 新增节点类型 `slot`；`component` / `instance` 从占位类型转为真实语义。
- `component` 节点新增 `propertyDefs`：组件接口定义。`instance` 节点使用 `componentId`、`mainId`、`propValues`、`overrides`。`slot` 节点复用 `name` 作为插槽名，实例侧用 `slotFilled` 标记是否被填充。
- 节点新增可选字段的形状：

```ts
interface ComponentPropertyDef {
  id: string;                       // 稳定 id，改名不影响实例值
  name: string;                     // 显示名，组件内唯一
  type: "text" | "boolean" | "instance";
  targetMainId: NodeId;             // 绑定到母版里的一个节点
}

// component
propertyDefs?: ComponentPropertyDef[];

// instance
componentId: NodeId;
mainId: NodeId;                     // = componentId，统一覆盖寻址
propValues?: Record<string, string | boolean | NodeId>;  // propId → 值
overrides?: Record<NodeId, NodeOverride>;                // mainId → 字段补丁

// NodeOverride：style 允许只覆盖子字段（如 fill），其余字段按 DocNode 形状
type NodeOverride = Omit<Partial<DocNode>, "style"> & { style?: Partial<NodeStyle> };

// slot
slotFilled?: boolean;               // 仅实例侧：是否已被用户填充
```

- 主组件必须是页面的直接子节点。创建组件时如果目标嵌套在画板/分组里，命令把它提升到页面顶层，并保持世界坐标不变。
- 组件里只能放实例，不能放组件；实例可以出现在任意容器或插槽里。
- 插槽不能嵌套在另一个插槽的默认内容里，命令直接拒绝。
- 插槽名在组件内唯一；属性名在组件内唯一；两者都允许改名，改名不改变内部 id。

### 实例物化与身份

- 插入实例时一次性物化整棵子树：实例根节点由调用方生成 id，子孙节点 id 由「父节点 id + 母版节点身份键」确定性派生（实例节点用自身 id，其它克隆用 `mainId`）。嵌套实例继续用同一规则递归，因此同一实例每次同步都得到相同 id。
- 实例根节点承载母版根的尺寸、样式、圆角与布局；位置属于实例自身，可见性默认也由实例自己持有（布尔属性可显式控制）。`mainId` 等于 `componentId`，它同时也是覆盖的寻址起点。
- 实例内部每个节点都带 `mainId` 指回母版里的对应节点。删除母版节点后，实例里对应节点随同步删除，相关覆盖丢弃。
- 实例根节点不渲染特殊边框；它按画板/矩形的样式规则渲染自己的填充与描边，内部子树照常绘制。

### 同步与撤销

- 任何命中母版内部节点的命令，在 `apply` 之前先做确定性展开：找出受影响的组件，按组件依赖的拓扑序，把「母版更新 + 所有实例重建」拼成一个批命令，再走现有的整批校验与逆命令记录。
- 重建按 `mainId` 做增量 diff，而不是整棵删除重建：匹配到的节点更新字段，母版新增的节点创建，母版删除的节点删除，顺序变化更新 `children`。这样选中状态、文本编辑态和已填充插槽内容不会被无谓打断。
- 重建顺序：克隆母版 → 应用组件属性 → 应用覆盖 → 已填充插槽保留原内容、未填充插槽克隆默认内容。
- 母版与全部实例属于同一个撤销步：一次撤销同时回退母版与所有实例，不出现中间态。
- 展开必须是纯函数：执行期不读时间、不用随机数、不调用 `newId()`；新节点 id 全部来自确定性派生。
- 组件依赖如果成环，在创建组件、插入实例、切换组件三个入口直接抛错，不进入展开。

### 覆盖

- 覆盖按字段记录：`mainId → NodeOverride`，只包含与母版不同的字段；`style` 可按子字段覆盖（如只冻结 `fill`）。
- 覆盖由命令层自动维护，GUI 与 AI 走同一条路径：编辑实例内部节点时，逐字段比对母版当前值，不同则写入覆盖，相同则删除该字段的覆盖。
- 实例根节点的编辑同样记为覆盖，`mainId` 为 `componentId`。
- 属性优先：被组件属性绑定的字段禁止写覆盖；检查器把该字段渲染成属性控件，而不是普通输入。
- 可覆盖字段：文本、样式、可见性、名称、几何、嵌套实例的属性与组件指向。父容器启用自动布局时，子项几何由求解器决定，几何覆盖不生效（检查器禁用并说明），其余字段照常。
- 覆盖的写入、清除与重置都进入撤销栈；撤销一次同时恢复字段值与覆盖表。
- 检查器支持逐字段重置与全部重置；重置后字段回落到母版当前值。

### 组件属性

- 属性从图层创建，隐式绑定一个目标字段：文本图层 → `text`；任意图层 → `visible`；嵌套实例 → `componentId`。
- 一个属性只驱动一个字段；不做「一属性驱动多图层」。
- 属性值缺省时回落到母版当前值；显式设置后即使母版再改也保持；清除后重新跟随母版。
- 删除属性时绑定字段回落到母版值，实例上的对应值一并删除；不支持改类型（要改就删了重建）。
- 属性绑定目标被删除时，属性一并删除，实例上的值随之清理。
- 实例替换属性的下拉列出文档内所有组件；候选必须通过循环校验。

### 插槽

- 母版里的插槽节点由选中容器转换而来：容器变成 `slot`，原有子节点成为默认内容；默认命名「插槽 N」，可改名。
- 插槽填充采用替换语义：实例一旦填入内容，默认内容不再显示；清空填充后重新克隆默认内容。
- 实例侧插槽节点用 `slotFilled` 标记填充状态；填充内容是实例拥有的真实节点，同步时不覆盖。
- 向插槽里新建节点、粘贴节点、拖入节点都自动标记为已填充；拖入走窄重父级命令，保持世界坐标不变。
- 删除母版插槽时，只要任一实例的该插槽已填充，命令拒绝并提示先清空；其它母版结构变化静默跟随。
- 空插槽在编辑模式绘制虚线占位与插槽名，导出与截图不包含占位；占位属于 UI 叠加层。

### 实例替换、尺寸与脱离

- 实例可以拖拽缩放，只改变实例框，不缩放内部内容，超出部分按容器规则裁剪。
- 尺寸是字段级覆盖：没改过尺寸的实例跟随母版，改过的实例保留自己的尺寸。
- 替换组件时：位置不变，尺寸采用新组件（旧根节点的尺寸覆盖随旧 `componentId` 一起丢弃）；覆盖按 `mainId` 交集保留；插槽内容按插槽名保留；新组件不存在的属性值丢弃。
- 未绑定实例替换属性的嵌套实例也能直接换组件，等价于覆盖该节点的 `componentId`。
- 脱离只影响当前实例：实例根转成 `frame`，继承实例的填充、描边、圆角与尺寸；子节点原样保留；插槽节点转成无填充的画板容器；嵌套实例保持为实例。
- 脱离后清空 `componentId` / `mainId` / `overrides` / `propValues`，属性注入的值已经落在节点字段上。
- 删除主组件时，直接引用它的实例在同一条命令里脱离；含主组件的页面被删除时先确认，再按同样规则脱离。

### 渲染

- 画板渲染改为尊重节点样式：有填充才画底色，没填充透明；描边同理。画板工具新建画板时默认填入白色，保持现有视觉。
- 组件节点与实例节点按普通容器的样式规则渲染，移除现有的实例紫色虚线框。
- 插槽节点不画自己的背景；默认内容与填充内容照常渲染。
- 实例内部子树参与现有深度优先绘制、旋转、隐藏/锁定、非活动页淡化规则。
- 空插槽占位、插槽高亮、覆盖标记都是 UI 叠加层，不经过文档渲染路径。

### 画布交互

- 新增 UI 状态「实例上下文」：双击实例进入，`Esc` 逐级退出；未进入时实例按一个整体命中。
- 进入上下文后，内部图层按真实节点命中与选中；编辑走现有检查器、拖动、缩放与文本编辑路径。
- 拖动节点经过插槽时高亮该插槽；松手后节点成为插槽内容。不要求先进入实例上下文，指针进入插槽即可高亮。
- 禁止把节点拖进它自己的后代、禁止把实例拖进自己的插槽。
- 文本节点在实例上下文里双击进入现有行内编辑；提交后自动记为覆盖。
- 切换选中、切页、切模式、重新载入时清空实例上下文。

### 图层树与检查器

- 实例在图层树默认折叠；展开后显示内部图层，带覆盖标记（字段级小圆点）。插槽显示为「插槽 <名字>」并标注「已填充 / 默认」，空插槽显示占位项。
- 实例名默认跟随组件名；手动改名后不再跟随。主组件名可改，改名不改变实例的 `componentId`。
- 主组件检查器显示「主组件」标识与属性列表（新建、改名、删除）。
- 实例检查器显示组件名、属性控件、覆盖重置入口、「去主组件」与「脱离」。
- 属性控件按类型渲染：文本 → 输入框；布尔 → 开关；实例替换 → 组件下拉。

### 快捷键与入口

- 新增可配置动作：创建组件 `⌥⌘K`、脱离实例 `⌥⌘B`，归入快捷键面板的「组件」分组。
- 插入实例、去主组件、重置覆盖走面板与检查器按钮，不新增快捷键。
- `Esc` 在实例上下文里优先退出上下文，再按现有层级退出选中/工具。

### AI / MCP

- `read_document` 输出组件定义（`propertyDefs`）、实例（`componentId`、`propValues`、覆盖摘要）、插槽（名字、`slotFilled`、内容子树）。
- `create_node` 的 `kind` 加入 `component` 与 `slot`；`slot` 必须提供唯一名字。
- 新增工具：`create_instance`、`define_property`、`set_instance_prop`、`fill_slot`、`swap_instance`、`detach_instance`。
- `create_instance` 接受 `componentId`、父节点、位置、可选的属性值与插槽初始内容。
- `define_property` 接受目标节点、类型与显示名，返回属性 id。
- `set_instance_prop` 接受实例、属性 id 与新值；传 `null` 表示清除、回落到母版。
- `fill_slot` 接受实例、插槽名与已有节点 id，走窄重父级；`create_node` 以插槽节点为父节点时自动标记已填充。
- `update_node` 编辑实例内部节点时，覆盖由命令层自动记录，工具层不额外暴露覆盖参数。
- 组件相关的颜色仍只接受 Token 引用，字面量色值继续拒绝。

### 文件格式与文档

- `.sqraft` 的 `doc.json` 天然序列化新字段；旧文件没有这些字段时按「无组件」打开，无需迁移。
- 新增 ADR 记录组件模型：实体化实例、确定性 id、字段级覆盖、插槽替换语义、属性绑定。
- 架构文档的组件章节以字段级覆盖为准，并覆盖同步、插槽、属性、脱离与删除规则。
- 术语表补充「插槽」「实例上下文」「字段级覆盖」，修正「覆盖」不再是窄白名单。
- 路线图 M2 的组件系统标记为「部分交付」：本轮交付组件/实例/插槽/文本、布尔、实例替换属性；枚举与变体仍在范围内未交付。

## Testing Decisions

好的测试只验证外部可观察行为：给定命令与文档状态，断言文档里的节点关系、字段值、`mainId`、覆盖表、撤销后的状态；不测试同步实现内部调用了哪些命令，也不做 DOM/Canvas 快照。测试应能描述「用户看到的结果」，而不是「代码走了哪条分支」。

### 测试 seam

- **主 seam：`DocStore.apply(...)`**。组件系统的绝大部分风险都在命令层：创建、物化、确定性 id、级联同步、覆盖写入、属性优先、插槽保护、循环校验、脱离、删除、撤销原子性。沿用 core 现有的命令级测试写法，一个 seam 覆盖主要逻辑。
- **次 seam：`ToolExecutor`**。验证 AI 工具 schema 的读写效果与拒绝路径，沿用 ai-tools 现有的执行器测试写法。
- **E2E：Playwright**。只覆盖真正属于 UI 的部分：组件面板、插入、双击进入实例上下文、拖入插槽、覆盖标记与重置、脱离、快捷键、画板样式变化后的视觉结果。Web 客户端没有测试运行器，不为本规格引入新的单元测试基础设施。

### 测试内容

- 创建组件：单容器原地转换；多选包一层并重父级；嵌套容器提升到页面顶层且世界坐标不变；新组件命名正确；一次撤销回到创建前。
- 实例物化：插入后子节点数、`mainId`、派生 id 与母版一致；同一实例重复同步得到相同 id；实例根继承母版样式与尺寸。
- 级联同步：改母版文本/填充/尺寸后所有实例同步；嵌套组件（A 含 B 的实例）按拓扑序一次算完；同一撤销步同时回退母版与全部实例。
- 覆盖：编辑实例内部字段写入对应 `mainId` 的覆盖；改回母版值自动清除；母版改其它字段不覆盖已冻结字段；属性绑定字段拒绝写覆盖；覆盖写入与清除可撤销。
- 属性：文本、布尔、实例替换三种属性从目标图层创建；实例值设置/清除；删除属性回落母版；目标图层删除时属性删除；重名拒绝。
- 插槽：容器转插槽保留默认内容；实例未填充时克隆默认；填充后替换默认；清空恢复默认；填充内容在母版同步后保留；已填充插槽的母版删除被拒绝；插槽套插槽被拒绝。
- 替换：换组件后位置不变、尺寸取新组件；按 `mainId` 交集保留覆盖；按插槽名保留内容；新组件不存在的属性值丢弃。
- 脱离：实例转画板并继承样式与尺寸；插槽转无填充容器；嵌套实例仍为实例；脱离后可撤销回实例。
- 删除：删母版时实例脱离；删含组件的页面先确认；删除实例本身不影响母版。
- 循环：组件直接/间接嵌套自己被拒绝，且不产生撤销记录。
- 窄重父级：拖入插槽后节点世界坐标不变、旧父级 `children` 移除、新插槽标记已填充；拖进自己的后代被拒绝。
- 兼容：旧文档没有组件字段时能正常打开与编辑；现有 core / ai-tools 测试全部保持通过。

### 手工验证

沿用现有 Playwright 手工验证方式，不写进 CI。至少覆盖：

- 选区创建组件（单容器、多选、嵌套提升），组件面板出现新条目。
- 插入 3 个实例，修改母版文案/填充/尺寸，三处同步；撤销一次全部还原。
- 双击进入实例、改一个字段、检查器出现覆盖标记；重置该字段；再改母版确认覆盖保留或清除符合预期。
- 创建文本 / 布尔 / 实例替换属性，实例检查器出现对应控件，改值立即生效。
- 容器转插槽、实例填充、清空恢复默认、从实例外部拖入插槽。
- 替换组件、脱离实例，确认外观与层级；删除母版确认实例脱离。
- `⌥⌘K` / `⌥⌘B` 快捷键与快捷键面板改键。
- 画板无填充时透明、画板工具新建仍为白色。

## Out of Scope

- 枚举型组件属性、变体、组件集合（`component set`）与变体切换。
- 跨文件组件库、组件发布/订阅、团队库。
- 作用域插槽（母版向插槽内容传值）、插槽的默认内容再嵌套插槽。
- 通用拖拽重父级（拖进画板、分组、任意容器），本轮只做「拖入插槽」。
- 自动布局下的 hug 实例尺寸、布局结果与实例尺寸的双向联动。
- 一个组件属性驱动多个图层。
- 组件里再放主组件。
- 复制/粘贴、批量替换实例、实例的批量选择与批量改属性。
- 组件级样式隔离（例如实例强制使用母版 Token、禁止字面量）。
- 旋转后的精确命中（沿用现有「忽略旋转」的限制）。
- 跨页面批量更新进度提示、超大文档的同步性能优化。
- 协作、云端存储、增量操作日志。

## Further Notes

- 同步的难点不是「复制」，而是「在母版结构变化时保住覆盖与插槽内容」。实现时先写 core 的同步与覆盖测试，再动 UI；UI 只是命令层的调用方。
- 确定性 id 必须从第一天就遵守：如果在同步里调用 `newId()`，撤销、选中、AI 读写都会变得不可预测。
- 画板渲染改为尊重样式是一次跨功能视觉变化；实现时要顺带回归现有画板、页面和绘图工具的默认外观。
- 插槽保护发生在命令校验阶段，拒绝时文档必须逐字节不变、不进撤销栈。
- 交付顺序见本地 ticket 列表（01–11）；每个切片都以 `pnpm test && pnpm build` 为门槛。
