## 0.0.6

*English summary:* This release is about agents getting it right in fewer round trips. `read_document` now reads one page or one subtree instead of the whole file (42.7 KB instead of 334 KB per page on a 100k-node design), a new `search_nodes` tool finds nodes by name, text, type, token or component, and every write result carries warnings — zero-size nodes, clipped text, missing tokens — so an agent can correct itself without another call. Models without vision get a text summary of the screen. The UI and the `.sqraft` format are unchanged; agent tooling sees four breaking changes, listed below.

这一版改的是 **agent 干活的质量**，不是画布：读得更少、找得更准、写完自己知道哪里不对。界面和文件格式没有变化。

### 读取：只读需要的那一块

- `read_document` 新增作用域参数：`scope`（`page` / `subtree` / `document`）、`pageId`、`subtreeId`、`depth`（0–8，默认 1）、`limit`（默认 200，上限 1000）
- **默认行为变了**：不传参数只读「当前页的第一层」，不再整篇返回；整篇读取需要显式 `scope:"document"`（只给页面与组件摘要）或逐页读
- 返回体里的节点是扁平数组（先序遍历，每条带相对 `depth`），不再是二次编码的 JSON 字符串
- 组件母版当普通节点读：`subtreeId` 直接接受组件 id；`scope:"document"` 给页面与组件的 `nodeCount`
- 被 `limit` 截断时返回 `truncated` 与一句 `hint`（提高 `limit`、降低 `depth`、或读某棵子树），不提供游标

实测（100 页 × 1001 节点 ≈ 10.01 万节点的回归 fixture）：

| 读取方式 | 体积 |
|---|---|
| 默认（当前页一层） | 42.7 KB |
| 同一页读到底 | 334 KB |
| 整篇读取 | 33.4 MB |
| 一张卡片的子树 | 3.4 KB |
| `scope:"document"` 摘要 | 1.9 KB |

### 搜索：跨页面与组件母版

- 新增 `search_nodes`：按 `name` / `text` / `type` / `fillToken` / `strokeToken` / `componentId` 过滤（AND），至少给一个条件
- 命中行很轻：`id`、`name`、`type`、`parentId`、`rootKind` / `rootId`（长在哪个页面或母版里）、`path`（名称链）、`match`（字段 + 80 字符摘要）；不返回子树、不带坐标
- 默认搜所有页面与组件母版，`visible:false` 的节点连同子树跳过；`pageId` 可限定单页；命中到 `limit`（默认 20，上限 200）即停，`hasMore` 表示还有更多
- 100 页空文档上单次搜索约 23 ms；命中 20 条即停，不做全表计数

### 写入诊断：同一响应里告诉 agent 哪里不对

- 写工具返回里新增 `diagnostics`（**只在非空时出现**），只有 `warning` 一档：`ZERO_SIZE`、`TEXT_NO_FILL`、`TEXT_OVERFLOW`、`TOKEN_MISSING`、`OUTSIDE_PARENT`
- 覆盖全部写工具；一次调用最多扫 2000 个节点、报 20 条，超出给 `diagnosticsTruncated`
- **只警告**：不回滚、不阻断写入、不新增撤销步；一次工具调用仍然是一步撤销
- `inspect_layout` 复用同一套规则，几何行不变，只多一个顶层 `diagnostics`
- 新增的 `OUTSIDE_PARENT` 取代了原计划里的 `FAR_FROM_WORK`：判断「改动节点与父容器内容区完全不相交」（角标、图标伸出边界不报）；`SIBLING_OVERLAP` 因误报率高，本版没做
- 诊断范围只覆盖本次调用动到的节点；固定布局容器改尺寸后、没被布局搬动的子项落在容器外，本版不会报警（`inspect_layout` 仍能看到几何）

### 无视觉客户端

- `screenshot` 新增 `format:"text"`：返回区域内节点的世界坐标、解析后的填充/描边颜色（缺 Token 会暴露成 `#ff00ff`）、文字与同一套诊断，最多 200 个节点；`format` 省略时行为不变（仍返回 PNG）
- MCP `initialize` 现在下发五条工作规则（先搜索再读取、默认只读一层、处理诊断、无视觉用文本视图、一次调用一步撤销）；只有支持该字段的客户端会注入

### 兼容性：会破坏现有 agent 提示词

这一版对工具契约有四处破坏性变更，人的操作不受影响：

1. `read_document` 默认从「整篇」变成「当前页 + 深度 1」
2. 节点树从 `pages[].subtree`（字符串）改为扁平的 `nodes`（数组）
3. `includeComponentTrees` 不再展开组件树，只返回一句弃用提示
4. 组件摘要的 `w` / `h` 改名为 `width` / `height`；工具总数 30 → 31

- 文档格式不变（`formatVersion` 仍是 8）：0.0.5 与 0.0.6 可以互相打开
- 界面、快捷键、数据目录、已有文档的样式与排版均无变化
- 之前写死的提示词如果依赖「`read_document` 一次拿全稿」，升级后 agent 会只看到一层；把提示词换成「先 `search_nodes`，再 `read_document({scope:"subtree", subtreeId})`」即可

### 内部

- `packages/ai-tools` 按职责拆分：`tools.ts`（工具清单）、`args.ts`（参数校验）、`serialize.ts`（读取/搜索的序列化）、`diagnostics.ts`（诊断接线）、`handlers/*`（按域分派），入口只剩装配
- `packages/core` 新增纯函数 `diagnostics.ts`：不依赖 DOM，文本度量由宿主注入

### 安装提示

与 0.0.5 相同，安装包本身没有变化：

- macOS：已签名、未公证，首次打开到 **系统设置 → 隐私与安全性** 点 **仍要打开**
- Windows：安装器未签名，首次运行点「更多信息 → 仍要运行」；更新仍是手动下载

### 已知限制

- 诊断只到 `warning`：不会阻止写入，也不做自动修复
- `SIBLING_OVERLAP`（兄弟节点重叠）本版没有；设计里角标、叠层卡片是常态，误报风险高
- 实例 `overrides` 表里的 Token 引用不在 `TOKEN_MISSING` 扫描范围内（已知盲区）
- 文本替代视图最多 200 个节点，按世界坐标包围盒筛选，不处理裁剪与透明度；跨页面重叠时可能带出同区域其它页面的节点
- 搜索不做正则、模糊或跨文档匹配，也没有索引；命中即停，不返回精确总数
- `initialize` 的工作规则只有支持该字段的客户端会采用，其余客户端仍靠工具描述
- 中日韩文字使用各系统自带字体，同一文档在 macOS 与 Windows 上换行位置可能不同
