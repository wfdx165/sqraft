## 0.0.7

*English summary:* This release is about agents building more than one node at a time, and about making their work auditable. A new `create_nodes` tool creates a whole nested subtree in a single call — one transaction, one undo step — instead of dozens of `create_node` rounds. The activity pill now lists exactly which nodes each call touched, next to the warnings that call returned, and every entry is clickable. A document-level strict mode (off by default) makes agents reference design tokens for colors instead of writing raw hex. The `.sqraft` format goes 8 → 9 with a single new field, old files keep the permissive behaviour automatically, and 0.0.7 opens 0.0.6 files but not the other way round. Tool count 31 → 32; the UI, shortcuts and data directory are unchanged.

这一版把 agent 从「一次改一个节点」推进到「一次改一棵子树」，并且把它的改动**摆到台面上**；设计系统还多了一个只约束 agent 的严格模式。

### 批量建树：`create_nodes`

- 一次调用提交**嵌套节点树**，整棵树走一个事务、一个撤销步；此前生成一屏卡片要连续调十几次 `create_node`，每次都是独立的一步撤销
- 入参与 `create_node` **逐字段同构**（`kind` / `name` / `text` / `points` / `image` / `layout` / 全部样式字段），只多两处：
  - `id` 必须由调用方生成（命令确定性：id 在命令创建前分配，apply 期不生成）
  - `children` 表达层级，节点级不再接受 `parentId`
- **先全量校验再落库**：任一节点非法，整次调用回滚，文档不留半成品，错误里带条目路径（如 `nodes[0].children[2]`）
- 单次含子孙 **上限 500**，超出报 `TOO_MANY_NODES` 并提示分批
- `children` 内不能放主组件与插槽（这两种仍是 `create_node` 的职责）；组件实例仍用 `create_instance`
- 顶层可以放主组件（等价于 `create_node` 不给 `parentId`）
- 实测：15 个节点的卡片列表 **1 次调用**建完，自动布局、文本自动尺寸、诊断照常工作；一次撤销整树回退

### 变更清单：看得见 agent 改了什么

- 顶部胶囊点开后，连接详情下面多了两段：**「本次改动 N 个节点」**与**「诊断 M 条」**
- 每条 = 节点名 + 动作词（新建 / 修改 / 删除 / 移动 / 实例 / 文档），**点击即选中并定位**（与图层面板的定位同一条路径，带脉冲标记）
- 诊断条目按诊断码显示本地化说明（`diag.*`，四语）；未知码原样显示
- 单个节点被删掉后，清单里仍是**删除前**的名字（调用前就抄好了，整棵子树一起抄）
- 单次最多列 **200 条**，超出显示「还有 N 个未列出」
- 生命周期：
  - 保留到**下一次成功调用**覆盖；失败的调用不清（它没改文档，旧清单仍然准确）
  - **撤销 / 重做立即清空**；空撤销栈上的 ⌘Z 不动清单
  - **新建 / 打开 / 关闭文档也清空**——否则清单会指向上一份稿子的节点，点击定位静默无反应

### Token 严格模式（可选，默认关）

- 设计系统面板新增「**严格模式**」开关，**文档级**（随文件走：把稿子交给别人或 agent，策略一起过去）
- 开启后 agent 写 `fill` / `stroke` **字面量颜色被直接拒绝**，错误码 `TOKEN_REQUIRED`，并按**色距**给出最近的 3 个 Token（名 + 色值 + ΔE），没有颜色 Token 时提示先 `define_token`
- 色距用 **OKLab ΔE**（感知均匀；按 ×100 展示，否则 `#3366ff` 与 `#4477ff` 会一起显示成 `0.0`）
- 只拦 **MCP 写入**：检查器里手选颜色不受影响；`fillToken` 与字面量同时给时 Token 优先、不报错
- **只管颜色**：字号、圆角、间距等数字字面量不拦（"越界"没有共识，强行拒绝会让 agent 卡住）
- 开关本身是文档命令，**可撤销**

### 修复

- `create_node` / `create_nodes` 现在**拒绝未知 `kind`**：`createNode()` 本身不校验类型，以前传错类型会把无效节点写进文档，现在直接报错
- 最接近 Token 的 ΔE 之前按一位小数输出，OKLab 距离是 0–1 量级，两个差别明显的 Token 都显示成 `0.0`；改为 ×100 展示，排序与数值都可读

### 兼容性

- **文档格式 `formatVersion` 8 → 9**：只新增一个可选字段 `strictTokens`，缺省 `false`
  - 0.0.7 打开 0.0.6 的文件：自动迁移，行为与 0.0.6 完全一致
  - **0.0.6 打不开 0.0.7 存的稿**：会明确拒绝并提示版本（`error.newerFormat`），不会"尽量解析"出一份坏稿——这是 ADR-0029 的既定规则，跨版本协作请一起升级
- **工具数 31 → 32**；`create_nodes` 是新工具，其余工具的参数与返回体未变
- 界面、快捷键、数据目录、已有文档的样式与排版均无变化
- 唯一的行为性破坏：以前给 `create_node` 传无效 `kind` 会被静默接受（产出一个不可用节点），现在报错

### 内部

- `packages/core`：新增纯函数 `color.ts`（sRGB → OKLab 色距，不碰 DOM，可在 Node 下测试）；新增命令 `doc.setStrictTokens`（进撤销栈）；`formatVersion` 迁移按既有模式加一档
- `packages/ai-tools`：`CREATABLE_KINDS` 成为"能建哪些类型"的唯一真源（schema enum 与运行期白名单同源，不再两处手抄）；`handlers/nodes.ts` 拆出 `readKind` / `readShapeArgs` / `buildStyleFor` / `resolveImageRef`，单建与批量共用同一条构造路径
- 渲染层：新模块 `renderer/agent-report.ts` 承载变更清单（纯逻辑，可单测）；`store.replaceDocument()` 收口"换文档"这件事，避免以后新增入口时忘记清理 UI 状态
- 新增 **33 项测试**（批量建树 12、严格模式 10、变更清单 8、迁移与命令 3），合计 **856 项**

### 安装提示

安装包本身与 0.0.6 相同：

- macOS：已签名、**未公证**，首次打开到 **系统设置 → 隐私与安全性** 点 **仍要打开**（每个新版本更新后需要再放行一次）
- Windows：安装器未签名，首次运行点「更多信息 → 仍要运行」；更新仍是手动下载

### 已知限制

- 严格模式只覆盖 `fill` / `stroke` 的颜色；效果（投影 / 内模糊）里的颜色不受约束
- 严格模式只拦 agent，不拦人：检查器里手选的颜色照写（故意如此——人不该被自己的工具锁死）
- `create_nodes` 不建组件实例、不在 `children` 里建主组件或插槽；需要这些仍要单独调用
- 单次建树 500 个节点是拍板值，更大的结构需要分批；分批之间不是同一个撤销步
- 变更清单只保留最近一次成功调用，且最多列 200 条；不做调用历史
- 严格模式对数字 Token 无约束（字号 / 圆角 / 间距仍可写字面量）
- 中日韩文字使用各系统自带字体，同一文档在 macOS 与 Windows 上换行位置可能不同
