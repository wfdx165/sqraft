# 桌面壳：Electron、进程边界与文件语义

Sqraft 从"浏览器单页应用"改为**只在桌面上运行**的应用程序（macOS / Windows / Linux）。选 Electron 的直接理由只有三条，且都是浏览器给不了的能力：MCP 需要一个常驻的 Node 进程、文件需要系统对话框与原地写回、`.sqraft` 需要文件关联与拖拽打开。

## 进程边界

- **渲染进程是文档真源**：`DocStore`、命令层、渲染器、AI 工具执行器全部留在渲染层。
- **主进程只做三件事**：MCP 宿主、文件 IO 与系统对话框、窗口/菜单/生命周期。主进程不持有 `DocState`。
- 跨进程能力只经 `preload` 的白名单对象暴露（类型集中在 `shared/ipc`），渲染层拿不到 `require`、拿不到任意 IPC。
- `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`；外部导航与 `window.open` 拦截，外链只经 `shell.openExternal` 且限 http/https；权限请求默认拒绝；打包版加严格 CSP。

## 文件语义

- **全手动保存**：磁盘上的文件只在用户按保存时变化。明确不做自动保存、不做崩溃恢复快照——这是取舍，不是遗漏。
- 写盘用"同目录临时文件 + rename"原子替换；保存前比对 mtime，文件被外部改过时提示"覆盖 / 另存为"。
- 关闭窗口/退出时由主进程拦下，向渲染层询问是否有未保存改动。
- 主进程不理解 `.sqraft` 结构：序列化、解析、版本迁移只在渲染层；主进程只搬字节。

## 窗口形态

- **单窗口、单文档**。窗口只有两种状态：欢迎页，或一个文档。
- `Cmd/Ctrl+W` 关闭文档回到欢迎页，`Cmd+Q` 退出应用；重开文件走最近列表、拖拽、文件关联或第二实例转发。
- 单实例锁：重复启动只聚焦已有窗口，并把要打开的文件转发过去。

## Considered Options

- 双目标（Web + 桌面壳）：Web 版没有 CORS 下的模型能力，文件体验也弱；同时维护两条文件路径是纯成本。否决。
- Tauri：体积更小，但 MCP 的 stdio 宿主、Node 生态与自绘窗口的成熟度都不如 Electron。否决。
- 主进程持有文档 + 渲染层当视图：等于把单进程模型改成 C/S，会动摇"画布热路径直接读 DocStore"的不变式。否决。

## Consequences

- 渲染层不再需要能力探测分支；文件层只保留 IPC 一条实现。
- 桌面能力（文件、菜单、MCP）没有自动化 UI 回归，靠主进程纯模块单测 + 手点清单。
- 三平台只有 macOS 真验证；Windows/Linux 的打包与文件关联属于"配置齐备、未运行"。
- 应用内不再有任何模型密钥与直连请求（见 ADR-0004）。
