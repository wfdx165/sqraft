# ADR-0023：改稿操作的选择、排列与剪贴板语义

## 状态

已采纳（2026-10）

## 背景

编辑器此前只有"画"和"改属性"，没有"改稿"：不能复制粘贴图层、不能框选、不能多选缩放、不能调层级、不能分组、没有标尺参考线。AI 生成稿子后，人工修一遍的成本高于重画。

这一轮补齐这些操作，需要先定几件会长期影响模型的事：剪贴板载荷与降级规则、分组的数据语义、参考线存在哪、缩放的边界。

## 决策

### 1. 剪贴板走系统剪贴板的自定义 MIME

- MIME 是 `application/x-sqraft+nodes`，载荷是版本化 JSON：根节点顺序、扁平节点表、被引用到的 Token 定义、被引用到的图片字节（base64 内联）。
- `⌘V` 的优先级是 **sqraft 节点 > 图片 > 文本**；载荷版本不认识时提示并停止后续尝试。
- 跨文档降级：图片按内容哈希注册复用；缺失的 Token 连定义一起带过去、同名冲突保留目标值；母版不在目标文档的实例按脱离语义降级为画板（插槽转画板、清 `mainId`/`overrides`/`propValues`）。
- 复制主组件得到新的主组件，`propertyDefs.targetMainId` 与 `componentId` 一起重映射；复制实例仍指向同一母版。

理由：只用内存剪贴板无法区分"在别处复制了文本后回画布粘贴"，会粘出旧节点；自定义 MIME 让"剪贴板里有什么"成为事实，而不是靠时间戳猜。

### 2. 分组是轻量容器，语义对齐 Figma

- 组无填充、不裁剪、不承载自动布局；尺寸等于子节点并集。
- 缩放组 = 递归缩放子节点（组本身没有绘制内容，只改组的框什么也不会发生）。
- 解组把子节点提升到组的父级、保持世界坐标、插回组原来的位置。
- 跨父级选区分组时，组落在第一个节点的父级下，世界坐标不变。

### 3. 参考线属于文档

- `DocNode.guides?: { x: number[]; y: number[] }`，只对页面有意义，坐标是**页面本地坐标**。
- 参考线只画在 UI 叠加层：不进文档渲染、不进 MCP 截图。
- 显隐与网格/吸附开关是**应用级 UI 偏好**（localStorage），不进文档。

理由：参考线是"这张稿子的对齐基准"，换机器打开要还在；显隐是"我这台机器的习惯"，不该污染文件。

### 4. 缩放与旋转的边界

- 多选缩放按包围盒等比：几何、圆角、字号、描边宽、效果半径与偏移、图片裁切一起按比例；自动布局的 `hug`/`fill` 子项只缩位置、不写死宽高。
- 非分组容器（画板/组件）只缩自身框，不递归缩放内部子节点（组是唯一递归的情况）。
- 旋转绕世界坐标中心：单选中心=自身中心（位置不变），多选绕包围盒中心（位置与角度一起变）；角度归一到 (-180, 180]。

### 5. 新增命令一览

`node.duplicate` / `node.reorder` / `node.align` / `node.distribute` / `node.group` / `node.ungroup` / `node.scale` / `node.rotate` / `token.delete`。

全部经 `expand()` 展开成基础命令（`node.create` / `node.update` / `node.reparent` / `node.delete`），撤销、锁定校验与组件同步复用现有机制；一次 UI 手势或一次 MCP 调用 = 一条撤销记录。

## 后果

- 文件格式版本升到 4（新增 `guides`），3→4 迁移只补版本号。
- 图层面板改为倒序显示（与 Figma 一致），拖拽索引换算集中在 `planLayerDrop`。
- 菜单里不能再出现 `role: "copy"` / `role: "cut"`（会先于渲染层吃掉 ⌘C/⌘X），复制/剪切走显式动作项。
- 参考线暂不参与吸附：把参考线塞进现有 `GuideContext.targets` 会让间距标注算出无意义的值，需要单独设计吸附通道。
