# ADR-0033：大文档的打开与滚动性能

## Context

ADR-0032 做了根节点级视口剔除之后，从 Sketch 导入的大稿（1.5 GB、554 页、约 19.5 万节点、555 张图）
仍然"打开慢、滚动卡"。这次在真实桌面端里量（开发版 + Chrome DevTools Protocol 驱动滚轮、
`ioreg` 采样 GPU 利用率，M1 Pro）：

- **打开 7–11 秒**：主进程读文件 + IPC 结构化克隆整块字节 3–5 秒；渲染层 `unzipSync`（纯 JS inflate 263 MB 的 doc.json、
  再把 555 张图逐个复制）+ `JSON.parse` + 给每张图建 Blob 又 4–6 秒；
- **滚动卡顿**：画布 2D 已经走 GPU（Chromium 报告 `2d_canvas: enabled`、`skia_graphite: enabled_on`），
  但滚动时 GPU 利用率打满到 90–94%，120 次滚轮里有 51 帧超过 50 ms。逐项关闭绘制类型做消融实验，
  卡顿几乎全部来自**节点效果层**（投影 / 模糊每帧重新离屏合成）；其次是图片解码颠簸（6000×4004 的照片原尺寸解码
  占 96 MB，256 MB 预算只放得下两三张，滚动时反复淘汰、重解、重新上传 GPU）。

## Decision

### 打开

1. **流式取件代替 IPC 克隆**：主进程只登记"这个文件允许读一次"，返回 `sqraft-doc://file/<token>`；
   渲染层 `fetch` 它流式拿字节。凭证 128 位随机、一次性、60 秒过期，协议只服务主进程刚为打开文件登记的路径。
   CSP 的 `connect-src` 相应放行 `sqraft-doc:`；
2. **快速 zip 读取**（`zip-read.ts`）：按中央目录取条目，存储条目（图片本来就是 `level: 0`）返回原缓冲区的
   **零拷贝视图**，压缩条目交给原生 `DecompressionStream("deflate-raw")`（不是 Web Worker，不受 CSP 的 blob worker 限制）。
   ZIP64 / 加密 / 其它压缩方法 / 结构对不上一律退回 `unzipSync`；
3. 图片资源的 object URL **用到时才建**（检查器缩略图 / SVG 解码），不再为每张图复制一份 Blob。

### 滚动

4. **效果层与蒙版层跨帧缓存**：合成结果按 `节点 id @ epoch` 存在后端（LRU，192 MB）。平移只是整数像素平移，
   直接回贴缓存位图，跳过整棵子树的绘制。失效规则：
   - `epoch` = 文档对象 + `version` + 异步资源纪元（图片 / 链接图解码完、字体加载完、语言切换都会推进它）；
   - 缓存条目带变换签名（缩放、旋转与亚像素偏移），缩放或换屏（DPR 变化）自然不命中；
   - 本帧带预览（拖动 / 缩放 / 路径 / 布局让位）或正在行内编辑的节点**及其全部祖先**不走缓存；
   - **背景模糊不缓存**（它取样的是下面已画好的内容，平移后就变了）；
   - 设备尺寸超过 2040 像素的层不缓存（整块缓存会被降采样变糊），仍按原路径只合成可见部分；
5. **图片分级解码**：画布把"屏幕上需要的分辨率占原图的比例"传给宿主，宿主按 1/2^k 级别解码
   （`createImageBitmap` 的 `resizeWidth/Height`，原图尺寸读文件头拿，不先整图解码）。`ResolvedImage` 的宽高仍是原图像素，
   新增 `scale` 字段，后端取样时换算——裁切等上层逻辑不感知级别。缺更精细级别时先用已有的级别顶上（不闪占位），后台补解。
   导出、AI 截图、新插入图片仍然拿原图；
6. 解码缓存淘汰从"按解码先后"改为**按最近使用**，屏幕上正画着的图不会被别的图挤掉；
7. **整页缓存**：页面与根级主组件整块走同一套缓存（`root:<id>@epoch`，绘制范围取剔除用的保守包围盒 + 投影余量）。
   缩小看全局时一屏几十上百个页面，拖动时每页只回贴一张位图；淡化页面在回贴时乘 alpha，不再每页单开一张不透明度层。
   页面里有节点在预览 / 编辑时整页不缓存；
8. **缩放手势中拉伸旧缓存**：缩放每帧都变，精确签名不可能命中——改为把旧缩放下的同一内容按新尺寸拉伸回贴（旋转相同才行），
   缩放停下 150 ms 后宿主补画清晰。补清晰**分摊到多帧**：每帧重画预算约 30 ms，超出后仍可拉伸的内容先拉伸、下一帧接着画；
   正在写缓存的层内部不允许拉伸（否则模糊内容会被当成清晰结果存进缓存）；
9. **极小叶子跳过**：屏幕上不到半个设备像素的叶子（不含带可见效果的）不画；导出不传 `pixelRatio`，不受影响；
10. **只有一次绘制操作的半透明叶子**（只有填充或只有描边的形状、图片、无描边无装饰线的文本）直接乘 `globalAlpha`，
   不开离屏层——这时组隔离与逐操作乘 alpha 逐像素相同。

## 实测（同一份文档、同一台机器）

| | 改前 | 改后 |
|---|---|---|
| 打开（读取 + 传输 + 解析） | 7–11 s | 约 3.4 s（流式读取 1.7 s + 解析 1.7 s） |
| 首次滚入新区域：>50 ms 卡顿帧 / 120 次滚轮 | 51 | 2 |
| 回滚已访问区域：>50 ms 卡顿帧 / 最长帧 | — | 0 / 26 ms |
| 滚动时 GPU 平均利用率 | 75%（峰值 94% 持续） | 46–54% |
| 滚动 120 次期间的图片解码 | 240 次、3.17 亿像素 | 62 次、700 万像素 |

缩小看全局（浏览器里用真实渲染代码、1440×900 @2x、编辑模式非活动页淡化；图片按占位画）：

| 缩放 | 可见页面 | 拖动单帧：改前 → 改后 | 缩放手势单帧 | 缩放停下补清晰 |
|---|---|---|---|---|
| 30% | 16 | 49 ms → 15 ms | 15 ms | 1 帧、62 ms |
| 8% | 57 | 264 ms → 19 ms | 15 ms | 6 帧、最长 143 ms |
| 4% | 109 | 408 ms → 30 ms | 16 ms | 12 帧、最长 145 ms |

## Consequences

- 推翻 ADR-0018 的"离屏不缓存"：当时的判断是收益只在拖动场景、等有读数再做；大稿的读数给出来了。
  失效逻辑集中在两处：渲染器的 `volatileNodes`（预览 / 编辑）与宿主的 `epoch`（异步资源）。
  以后新增"不改文档却改变绘制结果"的东西（例如新的异步资源），**必须推进 `epoch`**，否则会看到旧画面；
- 缩放手势中与刚缩放完的几帧会短暂看到拉伸（发虚）的页面，随后逐帧变清晰——用"缩放时略糊"换"缩放时不卡"；
- 极小叶子跳过让缩到很小时的画面与逐个绘制有细微差别（不到半个像素的点 / 细线消失），导出不受影响；
- 缓存命中时整块位图 1:1 回贴，与逐帧合成逐像素一致；未命中的首帧要多合成一次整块（不再只合成可见部分），
  所以第一次滚入一片新区域仍可能有一两帧偏慢；
- 打开文件不再经过 IPC 传字节，主进程新增一个只读自定义协议；保存路径不变（渲染层序列化、IPC 交给主进程写盘）；
- 零拷贝视图让图片字节与整个文件缓冲区同生命周期：打开期间整份文件常驻内存（本来所有图片字节也都要常驻）。
