# 图片节点：资源内嵌、裁切矩形与同父蒙版

页面里要能放位图。三件事必须一起定，否则后面每加一个交互都要返工：**字节存哪**、**框与可见区域怎么解耦**、**蒙版用什么模型**。

## 存储

- 位图按内容哈希（SHA-256 前 16 位）命名，写进 `.sqraft` 的 `assets/<id>.<ext>`，zip 条目用 `level: 0`（PNG/JPEG 自身已压缩，再 deflate 只费 CPU）。
- `doc.json` 只记 `image: { assetId, naturalWidth, naturalHeight, crop }`；同一张图多处使用只存一份。
- 打开文件时把 `assets/` 注册进渲染层仓库（不解码）；渲染时按需解码，LRU 上限 256MB，缩略图与画布共用同一份 object URL。
- 资源缺失（老文件被裁过、文件被手改）时画占位块并在图层上标记，绝不静默跳过。

## 几何

- 节点 `width/height` 是**外框**，`crop` 是**原图像素坐标**下的可见区域，默认等于整图；缩放框是"把这块区域铺进框"，默认拉伸，`⇧` 锁比例。
- 裁切与缩放解耦后，"换框大小"和"换看的区域"是两个独立动作，替换图片也不会继承上一张的裁切。
- 插入时按原始像素落地，超过页面 80% 等比缩小；多张并排 16px；粘贴落在视口中心。
- 上限：单文件 20MB、边长 8192px；GUI 走 20MB，AI 工具只收 base64 且上限 5MB（一条 JSON-RPC 里 27MB 的字符串会把 CLI 与超时机制一起拖垮）。

## 裁切

- 双击图片进入裁切模式：框内拖动移动可见区域，拖四角/四边缩放可见区域，`Esc` 或点图外退出。
- 一次拖拽整体包在一个 `DocStore.transact` 里：移动中实时 `apply`，松手才落成**一条**撤销记录。

## 蒙版

- Figma 语义：下层节点打 `isMask`，遮罩**同一父级里它上方相邻的兄弟**；没有引用字段，删节点/移节点不用维护指针，撤销天然正确。
- 渲染时把被遮罩的子树画进离屏层，再用蒙版形状的 alpha 做 `destination-in` 合成回来；遮罩支持任意节点形状（矩形/椭圆/路径/文字/图片本身）。
- 蒙版只取**填充**（描边不参与，否则会多出一圈），节点 `opacity` 直接乘到 alpha 上（半透明蒙版 = 半透明裁切）。
- 配对规则在 core 的 `maskPlan()` 里，渲染器只按计划派发；图层列表按 Figma 习惯倒序显示（`children` 是「从下往上」的绘制顺序）。
- 约束：蒙版必须与目标同父且位于其下方；没有可遮罩的兄弟时蒙版不绘制。

## AI

- `create_node` 支持 `kind: "image"` + `image: { data, mimeType }`；`update_node` 的 patch 支持 `crop` 与 `mask`。工具数仍是 14。
- 只收数据、不收路径：`document.open` 拒绝路径那条约束保持不变，agent 读不到任意磁盘文件。

## Considered Options

- 只记原始文件路径：文件小，但换机器/移动文件就丢图，"打开老文件一片空白"比文件大更难解释。否决。
- 图片填充到任意矩形（Figma 的 image fill）：能力强，但与"图片是独立节点"的模型冲突，本次不做。
- `maskId` 引用任意节点：可跨父级，但要处理循环引用与悬空指针。否决。
- 资源即时垃圾回收：删节点就删字节，会让"保存后撤销"变成破图（撤销栈里的节点仍引用它）。本次不回收，随文档生命周期释放。

## Consequences

- `.sqraft` 体积随图片增长；保存仍是全量重写 zip，超过阈值（300MB）提示而不是静默卡死——体积在**打包前**估算，否则 zip 已经建在内存里，拦不住峰值。
- `formatVersion` 升到 3：读入时给图片节点补齐 `naturalWidth/naturalHeight/crop`；旧版本应用打开新文件会把图片渲染成空框（不崩），这是向前兼容的代价。
- 图片解码是异步的：第一帧画占位，解码完成后触发一次重绘。
