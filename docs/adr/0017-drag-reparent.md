# ADR-0017：拖拽换父级

日期：2026-10-29
状态：已采纳

## 背景

画布上的普通拖动只写旧父级里的 `x/y`：元素可以视觉上压在别的画板上，但父子关系不变，也就不受那个画板的裁剪与自动布局约束。跨页面则完全没有入口。插槽已经用 `node.reparent` 做过一次“换父级 + 保持世界坐标”，但通用拖拽一直是组件规格里的 Out of Scope。

## 决策

1. **一条手势路径**：删除独立的 `reorder` 模式，所有拖动都走 `move` + 落点判定；落在原父级的布局容器上就是 `node.reparent`（同父 + 插入索引）。重排与换父级共用一套预览、高亮与提交逻辑。
2. **实时落点**：每帧用 `dropTargetAt` 求指针下最深的画板/组件，没有就到页面根，页面外不换父级；松手才提交命令。
3. **双判定函数**：新建节点继续用 `containerAt`（可以落进组件），拖拽用新的 `dropTargetAt` + `dropAllowed`（不能进出组件、实例子树不参与）。组件结构变更只保留“选区创建组件 / 实例同步”两个入口。
4. **`⌘` 转绝对定位**：落进自动布局容器默认进流（投影索引 + 插入线、不吸附），按住 `⌘` 则保留世界坐标并设 `layoutAbsolute`。
5. **沉默拒绝**：不合法落点不画任何提示，松手按原父级平移。规则不允许不是操作失败，红框/toast 会让人误以为“差一点就能成”。
6. **跨页松手才切活动页**：拖动中只画目标页高亮，避免来回拖动时面板与页面反复跳动；切页直接写 `ui.activePageId`，不走 `setActivePage`（后者会过滤选区）。
7. **参考线跟随落点**：上下文按落点父级重算（单条缓存），布局落点不吸附。
8. **撤销不跟视图**：跨页落下后撤销只回文档，活动页不回退——视图状态不进入撤销栈，保持可预测。
9. **悬停子元素边界单独一层**：容器内一级子元素描边是只读信息层，手势中隐藏，不参与命中与文档。

## 后果

- 画布上的元素可以被真正组织进画板与页面，受裁剪与自动布局约束；跨页搬运不再需要“先切页再拖”。
- 拖动中每帧要遍历一次页面子树求落点（与 `containerAt` 同量级），大文档下仍有可接受的成本；子元素矩形按容器缓存。
- 活动页与文档可能短暂不一致（撤销后），已在规格中写明。
- 图层面板拖拽改层级仍未实现，作为后续独立需求。
