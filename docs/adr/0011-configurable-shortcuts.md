# 快捷键可配置与统一分发

快捷键此前散落在三处、且是硬编码：画布 `onKey` 里的 H/V、F/R/O/L/T、⌘±/⌘0/⇧1、⌘Z/⇧⌘Z、Delete；对话面板自己的 ⌘K；工具栏 tooltip 里写死的文案（其中 ⌘O/⌘S 根本没绑）。用户要改键，是一类明确的长期需求。

改为**一份注册表 + 一个全局分发器**（`apps/web/src/shortcuts.ts`）：

- 动作表声明 `{ id, group, label, default }`，默认键位是规范字符串（`⌘⇧Z`、`⇧1`、`Delete`）；
- 键位来自 `localStorage` 的**差异表**（只存与默认不同的项），读取时与默认表合并，因此新增默认动作不会污染老用户的覆盖表，恢复默认就是清空差异；
- 组件挂载时登记自己能执行的动作（`registerShortcuts`），分发器按当前键位查找并调用；画布不再自己解析组合键；
- tooltip 一律通过 `keyOf(id)` 取键位，改键后立即同步，杜绝文案与行为漂移。

规则：

- 合法键位 = 可选 `⌘/Ctrl`、`⌥`、`⇧` + 一个字母/数字/功能键；只按修饰键不算，继续等待输入；
- 与其它动作重复则拒绝并提示（不自动互换）；`⌘W/R/T/Q/N` 等浏览器保留键拒绝；
- `Delete` 与 `Backspace` 视为同义；`⌘/` 固定用于打开面板，否则"改快捷键的快捷键"被改坏就再也进不去；
- 单键快捷键在输入框内让位；文件与对话类命令（⌘O/⌘S/⌘K）全局生效。

## Consequences

- 快捷键是应用级 UI 状态，不进文档、不进撤销，`.sqraft` 文件不携带键位。
- `V` 合并为「编辑模式 / 选择」一个动作，避免两条记录共享同一键位。
- 面板是居中对话框（工具条的 `translate` 会形成 fixed 包含块，浮层方案不可靠），点行就地录制。
- 新增能力时若需要快捷键：先在 `ACTIONS` 加一行，再在组件里 `registerShortcuts`，不要回到 `keydown` 里写 if。
