# 欢迎页以 MCP 接入为主位

> 2026-10 修订：接入方式已改为本机 HTTP URL（ADR-0026），本文里"安装命令行工具 / `node <路径>`"的命令形态已过时；"欢迎页先回答服务在不在、怎么接上"的结论不变。

Sqraft 的差异化是"能被 agent 驱动"，而欢迎页原本只讲"轻量、纯本地的设计工具"，把这件事完全藏进了 `帮助 > 配置 MCP…`。现在欢迎页的信息顺序是：**服务状态 → 能干什么 → 怎么接上 → 开始设计**。文档态刻意不做同样的事，理由见下。

## 三态与动作

- `not-installed`（CLI 还没进 PATH）：主按钮是「安装命令行工具」，就地执行
- `idle`（装了但没人连）：主按钮是「复制接入命令」
- `connected`（有 agent 在线）：不再给动作，只报在线人数

三态只改状态行与主按钮，卡片结构不变——状态本身就是引导路径。安装失败时就地显示原因，配置面板入口始终在旁边兜底。

## 呈现约定

- 状态行只报**监听状态与在线人数**，不显示端点路径：路径是实现细节，复制命令已经在下一行，展示出来既占宽又不像产品信息。
- 一行能力描述（`N 个工具 · agent 可读写当前画布`），工具数从 `toMCPManifest()` 取，不写死；不放示例对话——静态示例容易把产品页做成营销页，且工具改名后要同步维护。
- 命令块单行等宽、右侧渐隐、悬停可看全文；复制的是完整字符串。命令形态跟随安装状态：未安装 `node <绝对路径>`，已安装裸 `sqraft-mcp`；JSON 配置始终用 `node` + 绝对路径（不依赖 PATH 与可执行位）。
- 命令块支持切换客户端预设：`Claude Code`（`claude mcp add …`）与 `OpenCode`（`opencode mcp add … --global -- …`）。两者指向同一个 CLI，只是命令行语法不同；默认选中 Claude Code，切换只换命令文本，不影响三态。
- 欢迎页与配置面板共用同一份 `McpSetupInfo`（`renderer/mcp-setup.ts` 的 store）：面板里装完 CLI，欢迎页的主按钮与命令立刻跟着变，不需要重开窗口。主进程仍是路径的唯一计算方。
- accent 主按钮仍然是「新建文档」。**信息层级 ≠ 按钮层级**：MCP 占主位，但用户每天的第一动作是做东西，不该每天被提醒"还有命令没复制"。
- 视觉沿用现有浅色 glass 体系，靠位置、字号与命令块立住重点，不引入深色终端块（全局固定浅色，材质反差会显得突兀）。

## 文档态不升级

编辑器里只保留"有 agent 连接时才出现"的胶囊（`已连接 N 个 agent` / `agent 正在修改…`）。编辑时画布空间优先，连接状态属于事件而不是常驻信息；欢迎页负责介绍与接入，文档态只回答"现在有没有人在改我的稿子"。

## CLI 文件名去掉扩展名

CLI 从 `sqraft-mcp.js` 改名为 `sqraft-mcp`：软链名、`claude mcp add` 里的命令名、分发文件名三者一致。文件自带 shebang 且可执行；未安装时仍可用 `node <绝对路径>` 运行。

改名要处理旧链接：`setup.ts` 的 `inspectEntry()` 把本地判定分成 `absent / current / stale / foreign`，`stale`（指向本应用 `bin` 下旧文件名）由「安装」就地替换成新链接，`foreign` 才拒绝覆盖。

## Considered Options

- 深色终端面板/hero 大数字：视觉更抢眼，但和固定浅色主题冲突，且欢迎页变成展示页而不是入口。否决。
- 把「复制接入命令」做成 accent 主按钮：一次性动作占据最高视觉权重，老用户每天被提醒。否决。
- 文档态也加常驻 MCP 面板：编辑时抢画布空间。否决。
- 提供「关闭 MCP 服务」开关：CLI 连不上时会自动拉起应用，"关掉"的表现是 agent 报错却看不出原因，更像坏了而不是更安全。能力收敛应走项目级权限，另议。

## Consequences

- 欢迎页需要新增两个状态来源：`listening`（服务是否在监听）与工具数；前者加进 `McpStatus`，后者从清单动态取。
- `McpSetupInfo` 仍是配置的唯一来源，欢迎页与配置面板共用，不重复计算路径。
- 欢迎页的文案是产品定位的一部分，改文案时要同步 `README` 与本节。
