# 节点效果：投影 / 内阴影 / 图层模糊 / 背景模糊

节点外观里新增一列**有序效果**（`style.effects`），四种类型共用一条合成管道：先把节点（自绘 + 全部子节点）画进离屏，再按顺序施加效果，最后合成回文档层。

## 四个判断

**为什么是有序数组而不是四个平铺字段。** 平铺字段（`shadow`、`blur`…）只能表达“一种效果一个”，而多层投影叠加、先模糊再投影是日常用法；将来加新效果类型也不用再改样式结构。效果是样式的一部分，编辑效果就是一次 `patch.style` 整体替换，撤销正确性直接复用既有不变式（ADR-0001）。

**为什么按子树合成而不是逐节点施加。** 逐节点模糊在子元素重叠处会露出接缝、在容器边缘糊不出去；按子树合成才是“给这个图层加效果”的语义。代价是每个带效果的节点需要一张离屏，因此只在真有可见效果时才开层。

**为什么颜色复用 `Paint` 而不是强制 Token。** 填充与描边本来就允许 Token 或字面量（检查器同时提供 Token 下拉与取色器），效果颜色沿用同一模型，检查器不用造第二套控件；“只能用 Token”是 agent 工具层的纪律，在 `assertToken` 一处强制即可。

**为什么离屏不缓存。** 画布只在脏标记置位时重绘，静止时零成本；手势期本来就该以跟手为先。内容指纹缓存的收益集中在“拖动别的节点”这一种场景，成本却是一套新的失效逻辑。先用开发态帧耗时读数（本帧离屏层数与合成耗时）观察，确有需要再单独做。

## 语义

- 效果作用于**节点合成后的结果**，不是逐子元素；
- 半径与偏移是**文档单位**：缩放时同比放大，导出时自动正确；
- 离屏画布按 `blur + |offset| + |spread|` 外扩（效果 pad），长边封顶 2048 设备像素、超出按比例降采样；
- 父容器 `clip=true` 时子节点的效果同样被裁掉；内阴影与两种模糊被节点自身圆角裁剪，投影不受自身圆角裁剪；
- 效果**不改变节点包围盒**：不影响分组边界、自动布局尺寸、对齐吸附与命中检测；
- 背景模糊取样“该节点之下、文档层已经画好的内容”，因此网格独立在自己的画布上（`网格 → 文档 → UI 叠加层` 三层），既不会被糊进毛玻璃，也不会盖住画板。

## 行为变更

**透明度改为组隔离**：`opacity < 1` 的节点改为“先合成子树、再整体乘一次 alpha”，而不是逐绘制操作乘 `globalAlpha`。这是修正 —— 半透明容器里重叠子元素的重叠处不再偏深 —— 但**现有文件的观感会变**，不是回归。

## Consequences

- 每个带效果的节点每帧至少一次离屏与一次合成；模糊节点是最贵的，靠降采样与 2048 封顶控制上限；
- 效果 pad 让“节点矩形”不再是准确的绘制边界，将来的视口剔除必须用扩边后的矩形；
- 组件实例的效果覆盖是**整组替换**（与填充同粒度），按条覆盖需要给 effect 引入稳定 id，目前不做。
