# 命令化文档模型：一切编辑都是可序列化命令

Sqraft 的文档不能被直接修改：一切变更（GUI 手势、AI 工具调用、撤销重做、自动保存）必须走可序列化为 JSON 的命令，文档状态是命令流的确定性结果。我们决定从第一行代码起就采用这一约束，而不是"先直接改对象、需要时再重构"。

这是所有其他决策的地基：撤销/重做免费获得、操作日志即文件格式的增量部分、崩溃恢复可重放、AI 工具天然落点、未来多人协作只是"多个命令源"。代价是前期约 20% 的额外设计成本，以及所有命令必须满足确定性纪律（禁时间/随机数/外部资源）。

## Considered Options

- 直接内存对象操作 + 前后快照做撤销：实现快，但文件格式、协作、录制回放全部要推倒重来——在设计工具领域"以后再重构"等于重写编辑器。
- Redux 式单向数据流但命令不落盘：得到撤销却得不到文件格式与重放能力。

## Consequences

- 任何破坏命令确定性的代码都是架构级缺陷，review 时一票否决。
- 大批量操作（如重排 500 个节点）需要命令级批处理，不能用循环 500 条命令代替。
