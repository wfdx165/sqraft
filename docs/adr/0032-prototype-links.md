# ADR-0032：原型链接与演示模式

## Context

Sqraft 的页面之间此前没有任何关系：每块页面都是一张静态图。要让稿子能"走一趟"（点击 → 切屏 → 返回），需要先有**边**。这条边也是后续动效（Smart Animate 式状态插值）的挂载点——没有 A→B 的链接，转场无处可落。

约束与边界（2026-11 与作者确认）：

- **形态**：Figma 式的图层级点击跳转，不是时间轴关键帧。
- **单位**：一次演示展示**一个页面**；链接目标只能是 `page`。理由是现有工作流里一屏就是一页（示例稿的三屏就是三页），页面本来就是固定尺寸的根节点。
- **范围**：只做 click；hover / press / delay / drag 后置。不做浮层（overlay）与变体间过渡（变体还没做）。不做导出（PDF / 视频 / 分享链接）。
- **不用原生全屏**：覆盖层放在窗口内，避免为一个视觉模式新增主进程 IPC 与平台差异。
- **滚动**：长页面必须能走查，所以页面支持 `scrollDirection`（none / vertical / horizontal），只在演示模式生效。

## Decision

1. **链接是节点上的数据**
   `DocNode.interactions?: Interaction[]`，每条是 `{ id, trigger: "click", action: "navigate" | "back", targetId?, transition: { type, durationMs } }`。不建文档级连线表：这样复制页面/画板时链接跟着走，也不需要第二份要同步的索引。代价是守一条纪律——**整组替换**（与 `patch.style` 相同），写入方先展开旧数组。

2. **引用完整性由命令层保证**
   - 删除页面时，指向它的链接在同一事务里清掉（`node.delete` 先展开成若干 `node.update`，撤销可原样还原）；
   - 换父级离开页面子树（拖进主组件、多选转组件）时自动清掉子树里的链接，而不是报错——拖拽莫名其妙的失败比丢一条链接更糟；
   - 跨文档粘贴时，目标页不在目标文档里就丢弃该条链接；
   - 实例物化 **不** 复制母版上的链接（实例子孙没有播放环境）。

3. **校验只写一次**
   `packages/core/src/interaction.ts` 的 `normalizeInteractions` 是唯一入口：≤8 条、id 唯一、目标必须是页面、不能是自己所在的页面、触发/动作/转场白名单、时长夹到 60–2000（`instant` 归零）。GUI 与 MCP 都走它，`validateOne` 抛错、`applyOne` 归一化。

4. **演示模式是纯 UI 状态**
   `ui.presenter = { pageId, scroll, stack }`：不写文档、不进撤销、**不改** `mode / activePageId / 视口 / selection`。因此"退出精确还原"是免费的不是实现出来的——覆盖层卸载即可。

5. **渲染复用导出路径**
   演示层用 `drawDocument(backend, doc, { onlyPageIds: [pageId] })` + `pageFitViewport`，把页面裁到自身矩形后应用滚动位移。命中从页面子树向下找，再向上冒泡到最近的热区；`H` 高亮所有热区。

6. **转场 v1 只有两档**
   `instant` 与 `dissolve`（旧屏抓图叠在新屏上淡出）。几何插值（Smart Animate）留给下一个 ADR；数据模型里的 `transition.type` 联合类型已经预留。

7. **AI 同一套前端**
   `set_interaction` / `remove_interaction` / `list_interactions` 三个 MCP 工具落在同一命令层，一次调用 = 一个撤销步；`read_document` 的节点摘要带 `links`，页面带 `scrollDirection`，agent 可以自检。

8. **格式版本 7 → 8**
   新字段全部可选，迁移是空步骤。**旧版本打开新文件会静默丢弃链接**——这是不发版的代价，写进发布说明。

## Considered Options

- **文档级连线表（`doc.links`）**：便于统一遍历，但复制、删除、撤销都要额外同步一份数据，且链接会脱离图层。否决。
- **屏幕单位 = 画板**：更接近 Figma（一页并排多屏），但当前工作流里一屏就是一页，页面也是固定尺寸根节点，先按页面把闭环做通。后续若要放开，只需允许 `targetId` 指向画板，不推翻结构。
- **每节点多条交互一上来就编辑**：模型支持数组（agent 可以写多条），但 UI 只编辑第一条，其余只读展示，避免一次做多触发的完整面板。分阶段。
- **演示层改 `ui.mode`**：会牵动画布、左栏、检查器与所有快捷键的语义。独立覆盖层更小、更难互相污染。否决。
- **原生全屏**：需要新 IPC 与平台差异处理，收益只是"更沉浸"。否决。
- **用视频导出代替演示模式**：导出管线（WebM / MP4）要动打包与依赖，演示模式本身已经是更好的验收与宣传素材。推迟。

## Consequences

- 新增属性必须同时想清楚**撤销、复制、删除引用、组件物化**四个方向；`interactions` 四个都覆盖了，后续新增引用型字段照此办理。
- 编辑器多了一层"只读播放"的语义：快捷键分发与画布手势都要在 `ui.presenter` 非空时让位（两处显式闸门，不依赖事件顺序）。
- 演示模式的验收只能手点（无自动化回归）：进入 / 跳转 / 返回 / 退出还原 / 滚动边界 / 热区高亮。
- 已知限制：一次只能编辑一条交互；不做转场打断重入（转场期间忽略点击）；不支持外部 URL 跳转；`back` 只退一屏，没有"回到起点"。
