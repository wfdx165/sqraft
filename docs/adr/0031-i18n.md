# ADR-0031：界面多语言（中文 / English / 日本語 / 한국어）

## Context

Sqraft 的界面从 0.0.2 起只有中文。要让它对非中文用户可用，需要在不破坏"纯单机、无后端、无账号"定位的前提下支持多语言界面。

约束与边界（2026-11 与作者确认）：

- **语言**：`zh-CN`、`en-US`、`ja-JP`、`ko-KR`。系统语言 `zh*` / `ja*` / `ko*` 分别匹配，其余回退英文；不做 RTL，不做更多语言。
- **翻译质量**：日/韩文案由 AI 按 Figma 官方术语起草，作者抽查菜单、欢迎页、设置与主要按钮等高频文案；接受"非母语级润色"，不静默承诺母语者审校。
- **选择方式**：默认 `auto`（跟随系统）+ 手动覆盖，存在 `preferences.json`；切换立即生效。老用户也走 `auto`。
- **范围**：只做用户界面——渲染层文案、原生菜单、系统对话框、Toast/错误、窗口标题、`index.html` 的 `lang`。日志、MCP 工具描述、README/docs、每个版本的更新说明不在本轮。
- **不做的**：`.sqraft` 文件里不存界面语言；文件格式不变；已打开文档里的字体不改。

## Decision

1. **共享 TS 字典 + 极简 `t()`，不引入 i18n 框架**
   `apps/desktop/src/shared/i18n/` 下放 `zh-CN.ts`（键的唯一真源）与 `en-US.ts` / `ja-JP.ts` / `ko-KR.ts`（类型上强制覆盖全部键）。主进程与渲染层共用 `resolveLocale` / `translate`；渲染层的 `locale` 是 Vue ref，模板随切换重渲染。插值用 `{name}`，复数用标签化措辞规避（`Tools: 3`），不引入 ICU。

2. **语言偏好**
   `preferences.json` 增加 `language?: "auto" | "zh-CN" | "en-US" | "ja-JP" | "ko-KR"`；缺省即 `auto`。主进程在 `initRecentFiles()` 之后解析并重建菜单；`app:set-language` 持久化、重建菜单、广播解析后的 locale。渲染层挂载前先取 `app.info()`，避免首屏闪语言。

3. **入口**
   轻量「设置」面板：`⌘,` + 应用菜单「设置…」，只放语言。语言选项是纵向列表（自动 / 中文 / English / 日本語 / 한국어），「自动」右侧显示当前解析到的语言。
   MCP 入口从「帮助」移到应用菜单「设置…」旁边（非 mac 平台放进「文件」菜单）；`McpSetupPanel` 本身不变。

4. **按语言切换 CJK 字体栈**
   界面 `--font` 由 `html[lang]` 切换：中文 PingFang SC / Microsoft YaHei，日文 Hiragino Sans / Yu Gothic / Meiryo，韩文 Apple SD Gothic Neo / Malgun Gothic。画布标签、tooltip、拖放与插槽提示、新建文本的默认字体共用 `renderer/font-stack.ts`；已有文档的 `fontFamily` 原样保留。切换语言时触发一次画布重绘。

5. **轻量日文禁则**
   `packages/core/src/text.ts` 的 `wrapParagraph` 增加两张小规则表：收尾标点（`、。，！？：；）］｝」』` 等）不出现在行首，开括号（`（［｛「『` 等）不出现在行尾。不做完整 JIS X 4051；必要时允许一行溢出 1 个字宽（与 Figma 一致）。中文一并受益。

6. **核心错误码**
   `packages/core` 对"用户操作能触发"的错误抛 `AppError { code, params }`；界面用 `localizeError()` 映射，未知错误显示通用文案、原始信息只进日志。纯内部不变式继续用普通 `Error`。
   MCP 面向外部 agent 的错误文案固定英文（`shared/agent-text.ts` + `agentErrorText()`），与界面语言解耦；端口/监听错误只进 `McpSetupInfo.error` 给设置面板，仍随界面语言。

7. **文档默认名跟随界面语言**
   页面、分组、组件、插槽、新建图层的默认名由渲染层按当前语言生成，并作为 `name` 随命令传入；core 只保留语言中性的兜底。`.sqraft` 仍是内容，不记录语言。

8. **回归防护**
   `src/shared/i18n/i18n.test.ts` 断言四种语言的键集合一致、无空值，并扫描 `.vue` 的 `<template>`，出现写死的中文即失败；同时覆盖 `resolveLocale` 的 `ja*` / `ko*` 分支与日文禁则换行。`menu.test.ts` 校验 MCP 入口位置与英文菜单标签。

9. **术语**
   英文采用 Figma 词汇（Frame / Auto layout / Slot / Instance…），日/韩同源；对照表在 `GLOSSARY.md`。新增词先补表再进字典。

## Considered Options

- **`vue-i18n` 只覆盖渲染层**：主进程（菜单、系统对话框、文件错误）仍需要第二套机制，最终维护两套字典。否决。
- **`i18next` 同时用于两端**：一套 API，但为四种语言引入完整框架，配置与体积收益不抵成本。否决。
- **只跟随系统 / 只手动**：前者不让用户在中文系统上用英文，后者首次启动要猜默认值。否决。
- **固定一个包含全部 CJK 字体的栈**：共享汉字永远优先命中中文字形，日文观感不对。否决。
- **引入完整禁则/断行库**：质量最高，但依赖与测试面大，和当前"轻量"定位不符。否决。
- **把 MCP 工具描述也本地化**：描述是给外部 agent 读的，和界面语言解耦更稳。推迟。
- **更新说明多语**：需要改 `latest.json` 协议与每个版本的发布流程；本轮保持单语。推迟。
- **核心直接按 locale 返回文案**：破坏 `packages/core` 的语言无关性，也影响 MCP 复用。否决。

## Consequences

- 新增界面文案必须同时补四份字典；漏一种会编译失败，模板写死中文会被测试拦下。
- 主进程与渲染层共用字典，菜单/对话框与页面使用同一套术语。
- 切换语言会重建菜单、重渲染界面并重绘画布，不重启；已打开的系统对话框不追溯。
- 已知限制：日/韩文案由 AI 起草 + 抽查，不承诺母语级润色；禁则只覆盖常见标点，不做完整日文排版；`auto` 模式下运行中改 macOS 系统语言需要重启应用；系统打开/保存对话框跟随 OS 语言；Finder 的文件类型描述是构建期元数据，无法随界面语言切换；更新说明仍是单语（见 ADR-0029）。
- 渲染层 bundle 因四套字典增加约 100KB（压缩前）；不引入运行时网络请求或懒加载。
