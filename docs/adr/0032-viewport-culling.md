# ADR-0032：根节点级视口剔除

## Context

v1 的渲染策略是"全视口重绘、不做剔除"（architecture.md §5），剔除被列为"撞墙后的升级项"。现在撞墙了：
从 Sketch 导入的大稿（`@sqraft/sketch-import`）一份就有 554 个页面、1211 个主组件、约 19.5 万个节点，
打开后平移、缩放、悬停都明显卡顿。读代码定位到两处每帧都与文档规模成正比的开销：

1. **淡化层**：编辑模式下所有非活动页都 `pushOpacity(0.35)`，而且不带包围盒，退化为**整屏大小**的离屏。
   553 个非活动页 = 每帧新建、清空、合成 553 张整屏画布（Retina 下一张就是几十 MB），即使这些页根本不在屏幕上；
2. **全量遍历**：`drawDocument` 每帧遍历并绘制全部根节点的整棵子树，与是否可见无关。

## Decision

在**根节点（页面 / 主组件）这一级**做视口剔除，子树内部不剔除。

- `drawDocument` 新增可选的 `cull: { rect, rootBounds, pad }`：根节点整棵子树的包围盒（外扩 `pad`）与可见区域 `rect` 不相交，就整棵跳过；
- 淡化页面的不透明度层改为按「该页包围盒 ∩ 视口」开层：不可见的页一张离屏都不开，可见的页层也只有它在屏幕上的大小；
- 包围盒由 `rootDrawBounds` 计算：单次自顶向下遍历（带仿射矩阵），O(子树节点数)；口径是**保守**的——旋转按四角变换、效果按 pad 外扩（与 `subtreeWorldBounds` 一致）、描边按整条宽度外扩、文本再按自身高度外扩一次（固定尺寸文本框可能溢出）、隐藏节点也计入；
- `createRootBoundsCache()` 由**宿主**（画布组件）持有，按「文档对象 + `version`」失效：任何命令、撤销 / 重做都会让 `version` 变化，`replace` 会换掉文档对象；
- 渲染期预览（移动 / 缩放 / 路径编辑 / 布局让位）不改文档、不进缓存：`drawDocument` 把预览所在的根排除在剔除之外；
- `pad` 由宿主按屏幕像素给（画布取 64 CSS 像素 ÷ zoom），覆盖页面投影（blur 32 + 偏移 10）这类不进包围盒的装饰；
- 不传 `cull` 的调用方（导出 PNG、选区导出等）行为不变。画布本身和 AI 视口截图启用剔除。

## 顺带修掉的两个离屏层缺陷

淡化层改成「页面包围盒 ∩ 视口」后，层不再从屏幕原点开始，暴露了 `Canvas2DBackend` 里两个原本被"整屏层"掩盖的问题
（嵌套在任何非整屏层里的内容都会中招，例如半透明分组里的蒙版滚到屏幕边缘）：

- **嵌套层坐标错位**：`worldRectToLocal` 一直用主画布的「世界 → 像素」矩阵换算，而离屏层位图的原点在父画布的 `device.x/y`，
  嵌套的蒙版 / 不透明度 / 效果层因此被裁错位置，内容整块消失（导入稿里弹窗的遮罩层就是这样丢的）。
  现在每个层记录自己的 `worldToDevice`，换算取最内层；
- **层边缘发糊**：层外接框带小数，而位图宽高是取整的，回贴时被拉伸 / 错半个像素。现在外接框向外取整到整设备像素，回贴 1:1。

验证方法：同一份 19.5 万节点的文档，逐像素对比"剔除"与"不剔除"两次渲染。修掉以上两点后，剩下的差异只在**页面投影**的
衰减带里——这是 Chromium 的行为：同一帧里只要先合成过任意一张离屏层，之后的 `shadowBlur` 光栅结果就会不同
（用 `pushOpacity` + `popOpacity` 一对空层即可复现，主画布状态前后完全一致）。现状下这种差异本来就随绘制顺序存在，肉眼不可辨。

## 为什么只在根节点这一级

- 根节点数量与节点总数无关，判定成本只有 O(根数)；子树内逐节点剔除要为每个节点算世界包围盒，开销与收益都集中在"单页就有几万节点"这种更极端的情况，先不做；
- 根节点之间互不嵌套，跳过一个根不会影响别的根的绘制顺序与合成；
- 包围盒失效只有一条规则（文档版本），不需要按节点追踪脏区。

## 为什么缓存放在宿主而不是渲染器

渲染器仍然**无状态于文档**（architecture.md §5）：`drawDocument` 只接收一个 `rootBounds(id)` 函数。
缓存只存派生几何，按文档版本整体失效，不可能读到陈旧的文档内容；离开画布的调用方不传它就不受影响。

## Consequences

- 渲染开销从"与文档总规模成正比"变为"与屏幕上可见的根节点成正比"；缩到能看见全部页面时仍要全部绘制（那是 LOD / 分层缓存的范畴，未做）；
- 每次提交命令后，下一帧会重算所有根的包围盒一次（O(节点总数)，19.5 万节点约几十毫秒）；拖动等手势期间只走预览，不触发重算；
- 包围盒是保守的：极端情况下（例如文本溢出超过自身高度一倍以上、且恰好在视口边缘外）可能被误剔除，余量可按需加大；
- 命中检测不在本 ADR 范围：它只深入活动页与（带裁剪的）主组件，不随文档规模放大。
