# 链接（远程）图片：只存 URL，字节走本机缓存

> 图片节点原来只支持"字节嵌入 `.sqraft`"。用户与 agent 都需要直接引用网上的图（图标、封面、占位图），
> 因此加一种**链接图**：文档只记 URL，字节按需抓取并缓存在本机。嵌入图保持不变。

## Context

- 现有 `ImageRef` 只有 `assetId`：字节在 `.sqraft/assets/` 里按内容哈希存，文件自包含、离线可用（ADR-0022）。
- 直接"渲染时加载远程 URL"不可行：渲染层 CSP 是 `connect-src 'self'`、`img-src 'self' data: blob:`；即使放开，跨域图片会污染画布导致 `toDataURL` 抛 `SecurityError`，导出与 MCP 截图都会坏。
- 用户明确选择"文件不要因为图片变大"：远程图不打包进 `.sqraft`，宁可让文件依赖网络（首次打开）。

## Decision

- **模型**：`ImageRef` 增加可选 `sourceUrl`，与既有 `assetId` 二选一；`crop` 变为可选（缺省整图）。
  `naturalWidth/Height` 在链接图首次抓取前为 `0`（尺寸未知），渲染时用解码结果补齐，
  用户真正裁切时才把真实尺寸写进文档。
- **抓取在主进程**（`main/image-cache.ts`）：渲染层拿不到网络，只暴露 `app.fetchImage(url)`。
  校验只拦链路本地地址（169.254/16、fe80::/10）与 `file:`/`data:`；**本机与私网放行**（本地图床是正常用法）。
  请求用 `net.request(redirect: "manual")` 逐跳跟随（最多 3 跳，每跳重新校验主机）：实测 Electron 45 的
  `net.fetch` 在 `manual` 下会直接取消请求，自动跟随时又不填 `redirected` / `url`，拿不到最终地址。
- **缓存**：`~/.sqraft/cache/images/<sha256(url)>` + 元数据（etag / last-modified / 最近使用）。
  上限 500MB，按最近使用淘汰；菜单里给「清除图片缓存」。
- **时机**：懒加载——进视口/导出/截图时才抓；同一 URL 每会话校验一次（`If-None-Match` / `If-Modified-Since`），之后直接读缓存。
- **失败语义**：服务器说变了就静默换新图；断网/404/超时一律用上一次缓存（`stale`），**不报错**；
  连缓存都没有就画占位（虚线框），导出照常成功（空框）。不做"导出前列出缺失 URL 并阻断"。
- **不嵌入**：不提供"把远程图打包进文件"。要交付就先在本地保存图片再拖进来。
- **入口**：AI 的 `create_node image.url` / `update_node imageUrl` 与 GUI 检查器的 URL 输入共用同一条路径。

## Considered Options

- **文档存 URL、渲染时直接加载**：破导出（画布污染）、破离线、破分享。否决。
- **导入时抓一次、字节进 `.sqraft`**：文件自包含但会变大，与本次诉求相反。否决（仍是本地图片的路径）。
- **每次打开重新下载**：多花流量、离线不可用；条件请求已经能拿到"变了就更新"。否决。
- **抓不到就报错 / 阻断导出**：打断交付；用户明确选择"用旧缓存、空框也照常导出"。否决。
- **禁止私网地址**：会挡住本地开发服务器与 NAS 图床，收益有限。否决（只拦链路本地）。

## Consequences

- `.sqraft` 交给别人时，对方首次打开需要联网；离线且没有缓存时看到的是空框。
- 缓存是全局按 URL 共享的：两个文件引用同一张图只存一份，「重新抓取」会影响所有引用它的文件。
- 旧文件完全兼容（没有 `sourceUrl` 就是嵌入图，`crop` 缺省按整图处理）；新文件用旧版本打开时链接图会空白——旧版本没有"版本太新"的检查，挡不住。
- 远程图不能当页面背景图（`backgroundImage` 仍只认 `assetId`），也不进 `.sqraft`；字体与本地图片不受影响。
- 地址校验与真正建连之间存在 DNS 重绑定窗口（TOCTOU）。桌面单机、URL 由用户/agent 主动给出，风险可接受；彻底堵死需要自己建 socket 锁定 IP，会破坏 SNI 与证书校验，不做。
